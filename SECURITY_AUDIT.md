# Security Audit — HumanityCards frontend

Scope: the static frontend in this repo (HTML + vanilla JS + the ethers v5 chain
layer). No backend. Date of audit: current branch.

Summary: the site is a read-mostly dApp with a single write path (mint). The only
state-changing call is `original.mineCard{value: price}()`, reachable only by an
explicit user click followed by an in-wallet confirmation. No approvals, no
delegation, no user-controlled contract targets. Issues found during the audit
were fixed in the same pass and are listed under each item.

Contracts (hardcoded, checksummed in `assets/js/data.js`):
- Original (mining): `0xbc9B96E7Aa6AFEA664f9D5fdDa168518eE20f2Cc`
- Wrapper (ownership): `0xf6f722590AF5F791f68d0ED88D27b72dDe1C70CA`
- Multicall3 (reads): `0xcA11bde05977b3631167028862bE2a173976CA11`

---

## 1. Transaction safety

| Check | Status | Notes |
| --- | --- | --- |
| No tx without explicit user click | PASS | `mint()` is called only from `startMint()`, wired to the Mint button's click handler. Nothing auto-invokes it. `init()` does an eager reconnect via read-only `eth_accounts` (no popup, no tx). |
| No `approve()` / allowance txs | PASS | The ABI exposes no `approve`; the code never calls one. This is a payable mint, not a token transfer. (UI wording changed from "Approve about X Ξ" to "Confirm about X Ξ" so it can't be mistaken for an ERC-20 approval.) |
| Contract address hardcoded, not user-derived | PASS | Targets come from `window.HCX.CA` / `window.HCX.WRAPPER` literals in `data.js`. There is no code path that reads a contract address from URL, query string, hash, `localStorage`, or the DOM. |
| URL params / DOM cannot change the target | PASS | No `location.search` / `URLSearchParams` / `document.write` anywhere. The hash router maps `location.hash` to a fixed `ROUTES` table (unknown → `home`); the route value never reaches a contract call. |
| Tx value from contract, not user input | PASS | `value` is `getCardPrice()` read live from the contract. There is no amount input field anywhere. |
| Gas limit capped | PASS (fixed) | `gasLimit = estimate * 1.2`, then hard-capped at `MAX_GAS = 1,000,000` so a malformed estimate can't set millions. `mineCard` really uses ~150–300k. |
| Chain check before write | PASS | `mint()` calls `ensureMainnet()` (switches via `wallet_switchEthereumChain` or errors out) before sending. The nav shows a red "Wrong Network" state when `chainId !== 1`. |
| Failure handling | PASS | Every case is mapped to a clear message: user-reject (silent return to pack), insufficient funds (checked before and after gas), would-revert / minted-out, on-chain revert (`status === 0`), replaced/dropped tx, network error, and a 120s timeout that surfaces the Etherscan link. |

## 2. Frontend safety

| Check | Status | Notes |
| --- | --- | --- |
| No `eval()` | PASS | None in shipped code. (The dev-only `*_harness.js` test scripts use `eval` and are not served or committed.) |
| `innerHTML` only with trusted strings | PASS | The single `innerHTML` use (`dangerouslySetInnerHTML` in `hcx-cards.js`) renders SVG generated by `card-variants.js` from the hardcoded roster, with figure names passed through `CARD.esc()` (escapes `& < > "`). No user-supplied string is ever written as HTML. |
| Dynamic/user text is text-only | PASS | All dynamic UI (roster search query, addresses, counts) is inserted as text nodes via the `h()` helper or `textContent`. The search query appears only inside text nodes ("Nothing matches …"), never as markup. |
| No sensitive data in `localStorage` | PASS | Only keys under `hcx_tl_*` (Timeline streak / wins / played / saved daily order). No private keys, seeds, or wallet secrets — the app never has access to those (signing is delegated to the injected wallet). |
| CSP-safe (no inline handlers/scripts) | PASS (fixed) | `index.html` has zero inline `<script>` blocks and zero inline event-handler attributes; all behaviour is attached via `addEventListener`. The redirect stub pages were rewritten to use `<meta http-equiv="refresh">` instead of an inline script. CSP `script-src` was tightened to drop `'unsafe-inline'`. (`style-src` keeps `'unsafe-inline'` because the design uses inline element styles — lower risk, no script execution.) |
| SRI on external scripts | PASS (fixed) | The one external script (ethers 5.7.2 from cdnjs) now carries `integrity="sha384-…"` + `crossorigin` + `referrerpolicy="no-referrer"`. Verified the page still loads under SRI enforcement. |
| No mixed content / CORS issues | PASS | Everything is HTTPS (fonts, ethers CDN, RPCs). `upgrade-insecure-requests` added to the CSP. |

## 3. Data integrity

| Check | Status | Notes |
| --- | --- | --- |
| Addresses checksummed & correct | PASS (fixed) | Both contract addresses are EIP-55 checksummed; verified in-browser with `ethers.utils.getAddress(addr) === addr`. (The wrapper was previously lowercase; now checksummed.) |
| ABI matches the deployed contract | PASS | Verified against mainnet with `cast`/ethers: `getCardPrice`, `getHumanNumber`, `getHumanInfo`, `getCardInfo`, `balanceOf`, `mineCard`, and the `Mined(address,uint16)` event all resolve. The wrapper is **not** ERC721Enumerable on-chain, so ownership is read via `getCardInfo` + `wrapper.ownerOf` (validated against a real holder) rather than `tokenOfOwnerByIndex`. |
| RPC fallback | PASS (fixed) | Reads use `StaticJsonRpcProvider` (pinned network → no per-call `eth_chainId` probe that could stall) across three endpoints with manual failover: on error the next endpoint is tried, up to one full pass. Verified that a dead primary falls through to a live endpoint. |
| Chain-ID check prevents wrong-network tx | PASS | See "Chain check before write" above. |

## 4. Performance

| Check | Status | Notes |
| --- | --- | --- |
| Don't fetch all 239 minted counts on page load | PASS (fixed) | `init()` no longer refreshes on load. Minted counts are pulled **after first paint** (`setTimeout(…, 0)` in the renderer), non-blocking; the UI renders immediately from the snapshot in `data.js` and updates when the read resolves. |
| Batch / multicall | PASS | All 239 `getHumanInfo` calls and the full `getCardInfo` ownership scan go through **Multicall3** in chunks — never 239 separate JSON-RPC requests. |
| Cache RPC results | PASS (fixed) | Minted counts cached with a 60s TTL (`ensureMinted` is a no-op while fresh and de-dupes concurrent calls); `getCardPrice` cached with a 30s TTL. Verified the cached price call returns in ~0ms and `ensureMinted` within TTL does not refetch. |
| Don't block the UI on RPC | PASS | Reads are async and off the render path; the page is fully interactive before any RPC resolves. |

## 5. Wallet support (EIP-1193)

- Connection uses the standard `window.ethereum` provider — no wallet-specific
  code, no WalletConnect or other heavy SDK. Works with MetaMask, Coinbase
  Wallet, Rainbow, Rabby, Trust, Brave, Frame, and any EIP-1193 wallet. When
  several wallets are installed they expose `window.ethereum.providers[]`; the
  default `window.ethereum` is used.
- `accountsChanged` and `chainChanged` are handled (re-read ownership / update
  network state; empty accounts → disconnect).
- No-wallet handling: desktop shows "Install an Ethereum wallet extension…";
  mobile shows "Open this page in your wallet's in-app browser…". No deep-linking.
- All UI copy says **"Connect Wallet"** — no wallet is named anywhere in the UI.

## Residual notes / non-issues

- `style-src 'unsafe-inline'` is retained because the ported design sets element
  styles inline. This permits inline **styles**, not scripts, and carries no
  script-execution risk. Removing it would require extracting every component
  style to classes — deferred as a non-security cleanup.
- The injected wallet performs its own RPC for signing/broadcast; those requests
  are not page-origin fetches and are not constrained by the page CSP. The
  page-origin `connect-src` is pinned to the three read RPC hosts + `'self'`.
- Mint pre-checks read live state (price, supply, balance, gas) but the actual
  broadcast still requires the user to approve the transaction in their wallet —
  the frontend cannot move funds on its own.
